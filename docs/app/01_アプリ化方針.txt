MEFX-S3 アプリ化方針 01
======================

目的
----
現在のWeb/PWA版を、普通のアプリ開発の流れに乗せて「インストールして使うアプリ」に近づける。

この資料でいう「普通のアプリ開発」
----------------------------------
1. 要件整理
   - 誰が、何を、どの順番で使うかを決める。
2. 画面設計
   - 必要な画面、ボタン、状態、エラー表示を決める。
3. UX設計
   - 初回接続、プリセット作成、YouTube解析、送信失敗などの流れを自然にする。
4. 技術設計
   - アプリ本体、Bluetooth通信、解析サーバー、ESP32通信の分担を決める。
5. 実装
   - 画面、データ保存、Bluetooth、解析連携を作る。
6. テスト
   - シミュレーター、ESP32実機、未接続、失敗時を確認する。
7. 配布
   - Windowsアプリ、Androidアプリなど、使う形にパッケージする。

今おすすめの進め方
------------------
最初は「Windowsデスクトップアプリ」を作る。

理由:
- YouTube解析やDemucsはPCローカル処理が向いている。
- いまのWeb/Reactコードをかなり流用できる。
- PC上でESP32とのBluetooth接続確認を進めやすい。
- 画面やUXを固めたあとで、Androidアプリへ移植しやすい。

候補技術
--------
第1候補: Electron + React + TypeScript
- 普通のWindowsアプリとして起動できる。
- 今あるReact画面を流用しやすい。
- 解析サーバーをアプリ起動時に一緒に立ち上げやすい。
- BluetoothはElectron内のWeb Bluetoothから始め、必要ならネイティブ実装へ進める。

第2候補: React Native
- Android/iPhoneアプリ向き。
- Bluetoothはスマホ実機との相性がよい。
- ただしPCローカル解析との統合は別設計が必要。

第3候補: Flutter
- 本格的なスマホ/デスクトップアプリ向き。
- UI品質は高く作りやすい。
- ただし今あるReactコードはほぼ作り直しになる。

今回の判断
----------
まずは Electron + React + TypeScript でWindowsアプリ化する。

作るべきアプリの役割
--------------------
1. Manual Editor
   - ギター/ベース切替
   - 6種類のエフェクト値を0から100で調整
   - プリセット名を付ける
   - ローカル保存
   - ESP32へ送信

2. YouTube Tone Match
   - YouTube URL入力
   - ギター/ベース選択
   - PC内解析を実行
   - 推定プリセットを表示
   - 手動修正してESP32へ送信

3. Device
   - ESP32接続
   - 接続状態表示
   - 本体プリセット一覧
   - 本体プリセット読込/削除
   - 入力/出力前/マイク音量の簡易メーター表示

4. Settings
   - 言語選択
   - 解析サーバー状態
   - シミュレーター切替
   - Bluetooth診断

アプリ化で残すもの
------------------
- プリセット形式
- BLE UUID
- Manual Editorの考え方
- YouTube Tone Matchの流れ
- ローカル解析サーバー
- シミュレーター

アプリ化で作り直すもの
----------------------
- 画面構成
- ナビゲーション
- データ保存場所
- アプリ起動/終了時の処理
- 解析サーバーの同時起動
- Bluetooth権限/接続画面

最初の完成条件
--------------
- Windows上でアプリとして起動できる。
- シミュレーターでプリセット作成/保存/送信風の確認ができる。
- ローカル解析サーバーをアプリから起動できる。
- YouTube解析画面で仮解析または実解析結果をプリセットに反映できる。
- ESP32実機がある場合、Bluetooth接続とプリセット送信ができる。
