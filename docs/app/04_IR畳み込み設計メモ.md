# IR畳み込み設計メモ

## 目的

このアプリのTone Matchは、最終的にはYouTube音源からギター/ベース成分を抽出し、その音色に近づけるためのIRを作る、または近いIRを選ぶことを目標にする。

## 全体の流れ

```text
YouTube URL
↓
yt-dlpで音声取得
↓
ffmpegでWAV化
↓
Demucsでギター/ベース成分を抽出
↓
抽出音の周波数特性を解析
↓
IRまたはIR相当のEQカーブを作る
↓
Preset.ir に保存
↓
Audio FXではConvolverNodeでPC入力音に適用
↓
ESP32側には処理能力に合わせて軽量化して送る
```

## IRで得意なこと

- キャビネットらしさ
- マイク位置っぽさ
- 空間の響き
- 周波数特性のコピー

## IRだけでは苦手なこと

- 歪み量
- コンプレッサーの動き
- ピッキングへの反応
- アンプの非線形な挙動
- コーラスなどの時間変化

そのため、IRだけに頼らず、既存の6パラメータも使う。

```text
gain
tone_eq
compressor
drive
modulation
delay_reverb
ir
```

## プリセット内のIR情報

`Preset.ir` は任意項目にする。古いプリセットを壊さないため。

```json
{
  "enabled": true,
  "source": "generated",
  "name": "Guitar Match IR",
  "mix": 70,
  "lengthMs": 120,
  "sampleRate": 44100,
  "filePath": "app-ir://generated/...",
  "createdFromUrl": "https://www.youtube.com/watch?v=...",
  "notes": ["Demucs guitar/bass extractionから生成"]
}
```

## PC Audio FX側

PCではWeb Audio APIの `ConvolverNode` を使う。

```text
input
↓
gain / compressor / drive
↓
ConvolverNode
↓
modulation / delay_reverb
↓
output
```

## ESP32側

ESP32-S3で長いIRをそのまま使うのは重い可能性がある。

方針:

- PCアプリでは高品質IRを使う
- ESP32 v1にはWAV IRも`deviceTone`も送らず、基本6エフェクトの値だけを送る
- `deviceTone` は cabinet / presence / resonance / air / irMix を0〜100で持つPC側プレビューとし、ESP32への送信は将来拡張とする
- BLEでは `ir.filePath` やWAV本体を扱わない
