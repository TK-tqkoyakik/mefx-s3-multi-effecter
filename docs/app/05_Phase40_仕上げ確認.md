# Phase 40 仕上げ確認

このメモは、Windowsデスクトップアプリ版を「いま確認できるところまで」仕上げた状態を整理するためのものです。

## 現在の前提

- アプリ本体は `apps/desktop/` にある。
- Web/PWA版は残し、デスクトップアプリ版とは分けて進める。
- 外部の有料APIは使わない。
- YouTube解析、Demucs、IR生成、Audio FXはPCローカルで処理する。YouTube音声の取得には通信が必要。
- PC用の長いWAV IRはAudio FXで使う。`deviceTone`はPC側プレビューに留め、ESP32 v1には基本6エフェクトの値だけを送る。
- 最新製造データは [07の案内](../pcb-assembly/README.txt) を参照する。旧04/05/06は発注に使わない。
- 基板と手はんだ用部品は到着済み。部品面を上にして直配線で1枚を机上確認し、ケースへの組み込みは後回しにする。
- 音声回路はCS4270構成。PCM1808/PCM5102Aの別モジュール構成ではない。
- 音声入出力を含む基板全体の実機フル検証は未完了。「部品待ち」とは区別する。

## アプリ側の実装済み機能

以下は現在ソースにある機能であり、クリーンな別PCや実ESP32での動作保証ではない。

- Dashboard、Manual Editor、Tone Match、Audio FX、Audio Files、Library、Settingsの画面がある。
- 日本語/英語の切り替えができる。
- Manual Editorでプリセットを編集できる。
- プリセットをアプリ内に保存、読込、削除、名前変更できる。
- シミュレーターでESP32なしの接続、メーター、送信確認ができる。
- Tone Matchで推定プリセットとIR候補を作れる。
- YouTube音声をyt-dlpで取得し、Demucsで分離する。ギターは `other`（他の楽器も含む）、ベースは `bass` ステムを解析する。
- Demucsが未準備・失敗の場合は、ギターは中高域、ベースは低域のフィルター抽出へ切り替える。ギター単独分離を保証するものではない。
- IR候補をLibraryへ保存できる。
- IRの生成元URL、長さ、mix、WAV有無、Audio FX読込可否を画面に表示できる。
- 生成IRをWAV化できる。
- Audio FXでWAV IRをConvolverNodeへ読み込める。
- Audio FXでIRあり/なしをA/B比較できる。
- Audio Filesで手元の音声ファイルをWAVへ変換できる。
- Audio Filesで現在のプリセットの6パラメータを音声ファイルへ書き出せる。
- IRの名前変更、削除、WAVファイル破損チェックができる。
- Settingsで保存、解析、Bluetooth、IR Libraryの状態を診断できる。
- ESP32向け軽量トーン `deviceTone` をプリセットから作れるが、v1ではPC側プレビューと将来拡張用とする。
- [BLE仕様](../../shared/ble-contract.md) と送信実装では、長いWAV IRも `deviceTone` も送らず、音作りの値は基本6エフェクトだけを送る。
- ElectronのWeb Bluetooth経由で、MEFX-S3検出、GATT接続、プリセット送信、通知購読を行う入口がある。
- Windowsインストーラーを作る土台がある。
- インストーラーはインストール先を選べる形式にしている。
- GitHub ActionsでWindowsインストーラーを手動生成するworkflowがローカルにある。ただし `apps/desktop/` やworkflowなどはGit未追跡で、今回の変更はActionsへ未反映。

## 配布物・自動検証・実機記録の区別

- 既存配布物 `output/desktop/01_別PC配布/MEFX-S3 Desktop Setup 0.1.0.exe` は過去版。現在ソースの変更をすべて含むものとして扱わない。
- 現行0.1.1は `output/desktop/02_別PC配布/` のZIP。ビルドと同梱コードの照合を確認済み。NSIS生成はWindows署名ポリシーで中間プログラムが拒否され、未完成。
- 0.1.1で保存バックアップ/復元、破損復旧、解析進行/キャンセル、抽出方式明示、BLE異常系検査を追加。自動試験と実機試験は分け、詳細は `08_実機なし改善と追加調査.txt` を参照。
- 手元の単体テストは送信JSONや解析入力などの自動検証であり、実YouTube音源の分離品質、実機BLE、CS4270経由の音出しは検証しない。
- ビルド、`verify`、`verify:phase10.5`、インストーラー生成は、対象ソース・バージョンと実行結果を確認して記録する。過去版の成功を現在ソースへ引き継がない。
- [2026-06-25の実機記録](../firmware/01_ESP32-S3ファームウェア実機確認.txt) はESP32開発ボード単体の書き込み・起動・BLE広告などの確認。CS4270リセット解除やI2S初期化の起動ログは、製造基板での信号実測・音出し確認ではない。
- ローカル検証の成功をGitHub Actionsでの成功とは記載しない。本作業ではcommit/push/ブランチ作成を行わない。

軽量な自動検証は、`apps/desktop/` で `pnpm run test:device-preset`、`server/` で `pnpm test` を実行する。これらだけでは以下の実機未確認項目は解消しない。

## 次に進む条件

アプリ側の残り調整と新ビルドの検証を進めながら、到着済み基板を立ち上げる。[初回実装手順14](../hardware/14_届いた部品_初回実装手順.txt) を参照し、接続方法は [直配線接続表16](../hardware/16_直配線接続表.txt) と [R-78の向きと直配線図17](../hardware/17_R78向きと直配線図.txt) を優先する。J1からJ5へ直配線し、4本足端子台は使わない。

実機検証は次の順番がよい。

1. ESP32を挿さず、電源を外した状態で部品面を上に置き、短絡と直配線の極性を確認する。
2. 初回実装手順に沿って電源を測定し、電源を切ってからESP32を正しい向きで挿す。
3. 現在のfirmwareの書き込み・起動と、BLE広告名 `MEFX-S3` を確認する。
4. アプリから接続し、Manual Editorのプリセットを実機へ送る。
5. 本体プリセット一覧、保存、読込、削除を確認する。
6. `DeviceStatus` と `AudioTelemetry` の通知を確認する。
7. CS4270経由の音声入力、音声出力、フットスイッチを順番に確認する。ケースへの固定は机上確認後にする。

## 完了判定

アプリだけで確認できるPhase 40は、現在ソースのビルド、検証コマンド、新インストーラー生成が通り、対象バージョンと結果が記録されてから完了扱いにする。未追跡のローカルworkflowを、Actionsで稼働済みとは扱わない。

実機を使うPhase 37相当の完全確認と、音声回路を含む完成判定は、到着済み部品で別途測定・確認する。ローカルの自動検証が通っても、未確認の実機項目は完了にしない。
