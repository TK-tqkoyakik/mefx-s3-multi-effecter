MEFX-S3 UI/UX検討メモ 03
======================

アプリの基本方針
----------------
エフェクターを操作するアプリなので、派手な説明ページよりも、
起動したらすぐ「接続」「音作り」「送信」ができる画面にする。

想定ユーザー
------------
- ギター/ベースの音を作りたい人
- YouTubeの音に近づけたい人
- ESP32本体へプリセットを送って、スマホ/PCなしでも使いたい人

最初の画面
----------
Dashboard
- 接続状態
- 現在の楽器モード
- 現在のプリセット
- 入力/出力前/マイク音量メーター
- すぐ押せる「接続」「送信」「バイパス」

メイン画面構成案
----------------
1. Dashboard
   - 本体状態を見る。
   - 接続/切断。
   - メーター表示。

2. Manual Editor
   - 自分で音を作る。
   - ギター/ベース切替。
   - 6つのエフェクトを0から100で調整。
   - 保存、削除、ESP32へ送信。

3. Tone Match
   - YouTube URLから音色推定。
   - ギター/ベース選択。
   - 解析開始。
   - 推定結果をManual Editorへ送る。

4. Library
   - ローカル保存プリセット。
   - ESP32内プリセット。
   - 読込、削除、名前変更。

5. Settings
   - 言語。
   - シミュレーター。
   - 解析サーバー。
   - Bluetooth診断。

Manual EditorのUX
-----------------
- つまみ/スライダーは6個に絞る。
- それぞれ0から100。
- 値が変わったらすぐプリセットに反映。
- 送信前に「未接続」「値エラー」「名前なし」を分かりやすく出す。
- 保存と送信を別ボタンにする。
  - 保存: アプリ内に残す。
  - 送信: ESP32へ送る。

Tone MatchのUX
--------------
- URL入力欄は大きくする。
- 解析中は進行状態を出す。
- 失敗理由を短く出す。
  - 解析サーバー未起動
  - URLが空
  - YouTube取得失敗
  - パート抽出失敗
- 解析結果はすぐ送信せず、一度Manual Editorで確認/修正できるようにする。

Bluetooth接続のUX
-----------------
- 初回接続は手順を短く表示。
- 未接続でもシミュレーターで触れる。
- 接続後はデバイス名と状態を表示。
- 送信失敗時は「再接続」「シミュレーターに切替」を出す。

良い状態表示
------------
- 接続中
- 未接続
- シミュレーター
- 解析サーバー起動中
- 解析中
- 送信済み
- ESP32保存済み
- クリップ発生

避けたいUX
----------
- どのボタンを押せばよいか分からない。
- YouTube解析結果が勝手にESP32へ送られる。
- Bluetooth接続失敗の理由が分からない。
- 保存したのか送信したのか分からない。
- シミュレーターと実機が混ざって分からない。

画面の雰囲気
------------
- 楽器機材らしく、暗すぎない操作パネル。
- スライダーより「ノブ」表現も検討。
- ただし最初は実装しやすいスライダーで完成を優先。
- 文字は少なめ。
- 状態は色と短い文で伝える。

最初に作るUIの優先順位
----------------------
1. Dashboard
2. Manual Editor
3. Library
4. Tone Match
5. Settings

最初のプロトタイプでやること
----------------------------
- Windowsアプリとして起動する。
- 画面遷移ができる。
- シミュレーターでプリセット送信まで確認できる。
- 解析サーバーの起動状態が見える。
- 既存Web版と同じプリセット形式を使う。

あとで良くすること
------------------
- ノブUI
- 波形/レベルメーターの見た目改善
- プリセットの並び替え
- 音色の比較表示
- 実機ファームの状態ログ表示
- Androidアプリ化
